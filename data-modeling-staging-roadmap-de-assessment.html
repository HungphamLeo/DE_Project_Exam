1. Phân tích Dataset — Hiểu bản chất nghiệp vụ

Dữ liệu là gì? ⟶ Transport / Ride-hailing Events (taxi-like)

Mỗi hàng là một chuyến đi (trip event) đã hoàn thành trong Q4 2024. Đây là dữ liệu append-only fact — một event đã xảy ra thì không bao giờ thay đổi về mặt nghiệp vụ. Nhận diện dựa trên: zone_id, destination_id, passenger_count, duration, vendor_id, entity_id (driver/vehicle).

3. Schema Design — DDL Được Đề Xuất

3.1 — Raw Table (schema: raw)

Mục đích: landing zone — ghi trung thực từ CSV, không transform. Thêm _loaded_at và _source_file để audit. Dùng ON CONFLICT DO NOTHING để idempotent re-run.

-- schema.sql (raw layer) CREATE SCHEMA IF NOT EXISTS raw; CREATE TABLE IF NOT EXISTS raw.events ( event_id TEXT NOT NULL, event_timestamp TEXT NOT NULL, -- giữ nguyên TEXT lúc raw ingest entity_id INTEGER, zone_id INTEGER, destination_id INTEGER, vendor_id SMALLINT, event_type TEXT, rate_type SMALLINT, duration INTEGER, passenger_count NUMERIC(4,1), value NUMERIC(12,2), sub_value NUMERIC(12,2), total_value NUMERIC(12,2), payment_method TEXT, -- audit cols _loaded_at TIMESTAMPTZ DEFAULT NOW(), _source_file TEXT, CONSTRAINT pk_raw_events PRIMARY KEY (event_id) ); -- Partial index for incremental detection CREATE INDEX IF NOT EXISTS idx_raw_events_ts ON raw.events (event_timestamp);

3.2 — Dimension Tables (schema: staging)

dim_vendor SCD Type 1

Chỉ có 2 vendor (1, 2). Thuộc tính vendor (tên, quốc gia) nếu đổi thì overwrite — không cần lịch sử. UPSERT đơn giản.

dim_rate_type SCD Type 1

Bảng lookup nhỏ (5 values), static. Nếu định nghĩa rate thay đổi thì update-in-place là đủ.

dim_entity SCD Type 2

Entity (driver/vehicle) có thể thay đổi tier, vùng hoạt động, trạng thái. Cần giữ lịch sử để fact cũ vẫn join được version đúng.

dim_location SCD Type 2

zone_id & destination_id cùng dùng chung bảng location. Tên zone, borough có thể đổi. Dùng surrogate key để fact table join.

-- schema.sql (staging layer) CREATE SCHEMA IF NOT EXISTS staging; -- ── SCD Type 1: dim_vendor ───────────────────────────────── CREATE TABLE IF NOT EXISTS staging.dim_vendor ( vendor_id SMALLINT PRIMARY KEY, vendor_name TEXT, updated_at TIMESTAMPTZ DEFAULT NOW() ); -- ── SCD Type 1: dim_rate_type ────────────────────────────── CREATE TABLE IF NOT EXISTS staging.dim_rate_type ( rate_type_id SMALLINT PRIMARY KEY, rate_name TEXT, updated_at TIMESTAMPTZ DEFAULT NOW() ); -- ── SCD Type 2: dim_location (zone + destination unified) ── CREATE TABLE IF NOT EXISTS staging.dim_location ( location_sk BIGSERIAL PRIMARY KEY, -- surrogate key location_id INTEGER NOT NULL, -- natural key zone_name TEXT, borough TEXT, -- SCD2 validity columns valid_from DATE NOT NULL DEFAULT CURRENT_DATE, valid_to DATE, -- NULL = current is_current BOOLEAN NOT NULL DEFAULT TRUE, created_at TIMESTAMPTZ DEFAULT NOW() ); CREATE UNIQUE INDEX uq_dim_location_current ON staging.dim_location (location_id) WHERE is_current = TRUE; CREATE INDEX idx_dim_location_id ON staging.dim_location (location_id); -- ── SCD Type 2: dim_entity (driver/vehicle) ───────────────── CREATE TABLE IF NOT EXISTS staging.dim_entity ( entity_sk BIGSERIAL PRIMARY KEY, entity_id INTEGER NOT NULL, entity_tier TEXT, -- derived from avg metrics home_zone_id INTEGER, valid_from DATE NOT NULL DEFAULT CURRENT_DATE, valid_to DATE, is_current BOOLEAN NOT NULL DEFAULT TRUE, created_at TIMESTAMPTZ DEFAULT NOW() ); CREATE UNIQUE INDEX uq_dim_entity_current ON staging.dim_entity (entity_id) WHERE is_current = TRUE;

3.3 — Fact Table (schema: staging)

Bản chất của fact_trips: Đây là Transaction Fact (grain = 1 chuyến đi). Không bao giờ update, chỉ INSERT. Dùng foreign key đến surrogate key của dimension SCD2 để đảm bảo join ra đúng version attribute tại thời điểm trip xảy ra.

-- Fact table — append-only, grain = one trip CREATE TABLE IF NOT EXISTS staging.fact_trips ( trip_sk BIGSERIAL PRIMARY KEY, event_id UUID NOT NULL UNIQUE, event_timestamp TIMESTAMPTZ NOT NULL, -- Dimension FKs (surrogate keys → SCD2 snapshot) entity_sk BIGINT REFERENCES staging.dim_entity(entity_sk), pickup_sk BIGINT REFERENCES staging.dim_location(location_sk), dropoff_sk BIGINT REFERENCES staging.dim_location(location_sk), vendor_id SMALLINT REFERENCES staging.dim_vendor(vendor_id), rate_type_id SMALLINT REFERENCES staging.dim_rate_type(rate_type_id), -- Degenerate dimensions (no dedicated table needed) event_type TEXT NOT NULL, payment_method TEXT NOT NULL, -- Measures duration_secs INTEGER CHECK (duration_secs >= 0), passenger_count SMALLINT CHECK (passenger_count >= 0), fare_amount NUMERIC(12,2), surcharge_amount NUMERIC(12,2), total_amount NUMERIC(12,2), -- Audit _inserted_at TIMESTAMPTZ DEFAULT NOW(), _batch_id TEXT ); -- Partition-friendly index for time-range queries CREATE INDEX idx_fact_trips_ts ON staging.fact_trips (event_timestamp DESC); CREATE INDEX idx_fact_trips_entity ON staging.fact_trips (entity_sk); CREATE INDEX idx_fact_trips_date ON staging.fact_trips ((event_timestamp::date));

4. Chiến Lược SCD — Quyết Định & Trade-off

BảngSCD TypeLý doKỹ thuật áp dụng
dim_vendor Type 1 Tên vendor ít thay đổi, lịch sử tên không có giá trị phân tích INSERT ... ON CONFLICT (vendor_id) DO UPDATE SET ...
dim_rate_type Type 1 Lookup table cứng, định nghĩa rate ổn định Seed data, idempotent UPSERT
dim_location Type 2 Zone có thể đổi tên, borough, merge — cần biết trip cũ thuộc zone nào lúc đó Partial unique index WHERE is_current=TRUE, expire old row, insert new
dim_entity Type 2 Driver tier, home zone thay đổi theo thời gian — ảnh hưởng phân tích hiệu suất driver Surrogate key BIGSERIAL, validity window valid_from/valid_to
fact_trips Immutable Trip event là fact lịch sử — không bao giờ update về mặt nghiệp vụ INSERT ... ON CONFLICT (event_id) DO NOTHING → idempotent

⚠️ Trade-off cần lưu ý với SCD Type 2

  • Bài toán "lịch sử không có": CSV hiện tại không chứa attribute thay đổi của entity/location, nên lần đầu ingest bạn chỉ tạo 1 version "current" từ distinct values trong data. SCD2 machinery cần được thiết kế sẵn để khi có nguồn attribute thực thì chạy được.
  • Lookup khi load fact: Khi insert fact_trips, cần lookup entity_sk và location_sk theo WHERE is_current=TRUE và event_timestamp BETWEEN valid_from AND COALESCE(valid_to, 'infinity').
  • Đối với assessment này: Vì chưa có attribute thực của entity/location, có thể dùng entity_id trực tiếp trong fact (degenerate dimension) và note lý do trong README — đây là decision đúng đắn và honest.

5. Lộ Trình Triển Khai với Codebase Hiện Tại

Codebase hiện có gì?

PolarsEngine ✓ BasepolarssProcessor ✓ LoggerManager ✓ GreatExpectations config ✓ airflow_pipeline.py (trống) platforms/storage/postgre/ (trống) platforms/processing/kafka/ (trống) sql/ folder (chưa có)
  1. Tạo platforms/storage/postgre/postgres_client.py
    Wrapper cho psycopg2 với: connection pool, execute với retry, copy_expert cho bulk insert, tích hợp LoggerManager với handler logger.storage_log.postgre.
  2. Tạo sql/schema.sql
    DDL cho raw.events, staging.dim_*, staging.fact_trips như trên. Tất cả dùng CREATE TABLE IF NOT EXISTS + CREATE INDEX IF NOT EXISTS.
  3. Tạo sql/load.sql hoặc platforms/ingestion/ingest_csv.py
    (a) Raw load: dùng COPY raw.events FROM STDIN CSV HEADER — nhanh nhất với 300k rows.
    (b) Dim populate: UPSERT dim_vendor, dim_rate_type, dim_location, dim_entity từ DISTINCT values trong raw.
    (c) Fact insert: JOIN raw → dims để resolve surrogate keys, INSERT với ON CONFLICT DO NOTHING.
  4. Tạo platforms/ingestion/raw_ingestor.py kế thừa BasepolarssProcessor
    Override process(): đọc CSV bằng pl.scan_csv(), validate schema, gọi add_audit_metadata(), write đến Postgres hoặc Parquet intermediate.
  5. Viết orchestra/airflow_pipeline.py — DAG với 3 tasks
    task_ingest_raw → task_populate_dims → task_load_facts.
    Schedule: @daily. Idempotency: mỗi task dùng ON CONFLICT DO NOTHING hoặc DELETE WHERE batch_id = {{ ds }} trước khi insert.
  6. Viết sql/queries.sql — 2 analytical queries
    Ví dụ: (1) Revenue by zone per week, (2) Top entity performance với window function.
  7. Viết Kafka Producer & Consumer vào platforms/processing/kafka/
    Producer: đọc CSV row-by-row, publish JSON đến topic events.
    Consumer: consume, parse, insert vào raw.events (hoặc staging trực tiếp).

6. Load Strategy — Idempotent & Safe Re-run

-- load.sql: idempotent pattern cho từng layer -- 1) Raw: COPY + deduplicate bằng PK COPY raw.events (event_id, event_timestamp, entity_id, zone_id, destination_id, vendor_id, event_type, rate_type, duration, passenger_count, value, sub_value, total_value, payment_method, _source_file) FROM '/data/de_assessment_data.csv' WITH (FORMAT csv, HEADER true, NULL '') ON CONFLICT (event_id) DO NOTHING; -- 2) Populate dim_vendor (SCD1 UPSERT) INSERT INTO staging.dim_vendor (vendor_id, vendor_name) SELECT DISTINCT vendor_id, 'Vendor ' || vendor_id FROM raw.events ON CONFLICT (vendor_id) DO UPDATE SET vendor_name = EXCLUDED.vendor_name, updated_at = NOW(); -- 3) Populate dim_location (SCD2 — insert new NKs only) INSERT INTO staging.dim_location (location_id, valid_from, is_current) SELECT DISTINCT loc_id, CURRENT_DATE, TRUE FROM ( SELECT zone_id AS loc_id FROM raw.events UNION SELECT destination_id AS loc_id FROM raw.events ) z WHERE NOT EXISTS ( SELECT 1 FROM staging.dim_location dl WHERE dl.location_id = z.loc_id AND dl.is_current = TRUE ); -- 4) Insert fact_trips (idempotent — skip existing event_ids) INSERT INTO staging.fact_trips ( event_id, event_timestamp, entity_sk, pickup_sk, dropoff_sk, vendor_id, rate_type_id, event_type, payment_method, duration_secs, passenger_count, fare_amount, surcharge_amount, total_amount ) SELECT r.event_id::uuid, r.event_timestamp::timestamptz, de.entity_sk, dl_pk.location_sk, dl_dr.location_sk, r.vendor_id, r.rate_type, r.event_type, r.payment_method, r.duration, r.passenger_count::smallint, r.value, r.sub_value, r.total_value FROM raw.events r LEFT JOIN staging.dim_entity de ON de.entity_id = r.entity_id AND de.is_current = TRUE LEFT JOIN staging.dim_location dl_pk ON dl_pk.location_id = r.zone_id AND dl_pk.is_current = TRUE LEFT JOIN staging.dim_location dl_dr ON dl_dr.location_id = r.destination_id AND dl_dr.is_current = TRUE ON CONFLICT (event_id) DO NOTHING;
